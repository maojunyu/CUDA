# GPU 内存事务模型(Coalescing 详解)

> 配套内容:SGEMM V5(`kernel.cu` 的 `cudaSgemm_V5`)的 `float4` 加载与转置写入。
> 核心结论:现代 GPU 按 **32B sector** 为最小搬运单位,事务数 = 覆盖的 sector 数,利用率按 sector 内实际用到的字节计算。**128B 只是 L2 的记账单位,不参与浪费计算。**

---

## 1. 为什么"事务"必然存在:DRAM 的物理限制

DRAM 芯片不能按字节随机读,它按**突发(burst)**工作:一次给出行地址 + 列地址,连续吐出几十字节。地址线选行的开销是固定的,所以**一次传 1 字节和一次传 32 字节代价几乎一样**。

因此硬件规定最小传输单位——现代 GPU 是 **32 字节(sector)**。请求 4B 也会把 32B 整个搬来,28B 被浪费,这就是"利用率"的硬件根源。

```
请求 4B:   [████░░░░░░░░░░░░░░░░░░░░░░░░░░░░]  利用率 4/32  = 12.5%
请求 32B:  [████████████████████████████████]  利用率 32/32 = 100%
```

## 2. 存储层级与各级单位

```
SM 内 32 线程(warp)
      │  一条 LDG 指令,32 个地址
      ▼
  L1 Cache(每 SM 私有)     ← 同样按 32B sector 缓存(sectored cache)
      │  缺失的 sector
      ▼
  L2 Cache(全 GPU 共享)    ← 128B cache line = 4 个 sector
      │  每个 sector 独立 valid/dirty 位
      ▼
  DRAM(GDDR/HBM)          ← 最小突发 32B,sector=32B 的来源
```

关键点:**128B 只是 L2 的组织单位(line),真正的搬运和计数单位是 32B sector**。L2 缺一个 sector 就只从 DRAM 取那 32B,其余 3 个 sector 不动。"访问 32B 会拉来 128B"在 L2 这一级**不成立**。

## 3. 一次 warp load 的完整流程

```
① 32 个线程各发一个地址(同一条指令)
② 硬件把这 32 个地址按 [地址 / 32B] 分桶
③ 同一个 sector 内的请求 → 合并为一次传输
④ 不同 sector → 各占一次传输
⑤ 一次 warp load 的事务数 = 覆盖的 sector 数(1 ~ 32)
⑥ 利用率 = Σ(每 sector 实际用到的字节) / (sector 数 × 32B)
```

只看**一条 warp 级指令的 32 个线程**,与 block、grid 无关。

### 关键概念区分

| 概念 | 含义 | 数量级 |
|---|---|---|
| **访存指令(LDG)** | 一条 warp 级加载指令 | 每线程一条 |
| **事务(transaction)** | 一次 32B sector 搬运 | = 覆盖的 sector 数 |
| **线程请求** | 单线程一次读的字节 | 标量 4B,向量最多 16B(float4) |

> 一个事务 = 一次 32B 搬运,不是"一个线程的请求"。

## 4. 各类访问模式的利用率

### 每线程 4B(标量)

| 模式 | 地址分布 | sector 数 | 利用率 |
|---|---|---|---|
| 连续 `A[tid]` | 128B 连续 | 4 | **100%** |
| 错位 `A[tid+1]` | 128B 连续但偏移 4B | 5(前后各浪费半截) | 128/160 = **80%** |
| stride 2 `A[tid*2]` | 每 8B 取 4B | 8 | 128/256 = **50%** |
| stride 8 `A[tid*8]` | 每 32B 取 4B | 32 | 128/1024 = **12.5%** |
| 随机 | 全散开 | ≤32 | 最差 128/1024 |
| 广播 `A[0]` | 同一地址 | 1 | 100%(硬件广播) |

### 每线程 16B(float4,128-bit 向量化)

| 模式 | sector 数 | 利用率 |
|---|---|---|
| 连续 float4 `A4[tid]` | 16(每 2 线程 1 个) | **100%** |
| V5 的 A tile(2 线程一组,每组 32B 连续,组间跨行) | 16 | **100%** |
| V5 的 B tile(整行 512B 连续) | 16 | **100%** |

### 每线程 64B(概念扩展)

每线程 64B = 2 个 sector;一个 warp 32 线程 → **64 个 sector = 64 个事务**,不是 2 个。

但单条向量指令上限 128-bit = 16B,64B 必须拆成 4 条 `float4` 指令:

```
LDG.E.128 #1..4:每条 = 32×16B = 512B = 16 sector = 16 事务
合计:4 条指令 × 16 事务 = 64 事务,利用率仍 100%
```

**事务多 = 数据量本该这么多,不等于浪费;利用率才衡量浪费。**

### 单条 warp 指令的事务数上限

- 每线程 4B:最坏散到 32 个 sector → 最多 32 个事务
- 每线程 16B(float4):32×16B = 512B → 最多 16 个事务

## 5. 写事务的特殊性

- **读**:sector 搬来后各线程取自己的字节,天然支持"部分使用"
- **写**:write-back 缓存,写 4B 也要占一个 sector;部分写需 byte-enable 掩码(读-改-写)
- **L2 合并写**:同一 sector 的多次分散写可在 L2 先合并,再一次性写回 DRAM——scatter 写的代价比 scatter 读小
- **共享内存写不走这套体系**(smem 在芯片上直接按 bank 寻址),bank conflict 是另一套规则:32 banks × 4B,同一 bank 多地址才冲突

## 6. 历史:旧模型 vs 新模型

| 时代 | 模型 |
|---|---|
| G80 / GT200(CC 1.x) | 半 warp(16 线程)合并;128B segment 粗粒度,凑不满确实浪费 |
| Fermi(CC 2.x) | 引入 32B sector + sectored cache,粒度变细 |
| Volta ~ 现在 | 32B sector 全面成为 L1/L2/DRAM 的统一单位 |

> 直觉里"访问 32B 却拉来 128B"的模型来自 CC 1.x 时代,已过时。

## 7. 对 V5 代码的具体含义

1. **float4 的意义**:每线程 16B 请求,2 线程填满 1 个 sector,不多不少;指令数降为 1/4
2. **A tile 的 `row = i / 2` 映射**:让 warp 内相邻**两线程一组**落同一行连续 32B——若改成每线程一行,warp 32 线程散到 32 行,每行只用 16B/32B = 50%
3. **对齐是前提**:`kb` 是 8 的倍数、行宽 16384B 是 32 的倍数,保证每个 32B 段不跨 sector;若 `kb` 只是 4 的倍数,每段跨 2 个 sector,利用率掉到 ~50%
4. **B tile 同理**:warp 0 读整行 512B 连续 = 16 个连续 sector,100%

### V5 加载的数字账本(A 条带)

```
A 条带 = 128×8 = 1024 floats = 4096B = 128 个 sector
256 线程 = 8 个 warp
每个 warp:1 条 LDG.E.128 → 16 个事务
8 × 16 = 128 个事务 = 128 个 sector ✓(正好搬完,利用率 100%)
```

## 8. 测量方法(Nsight Compute)

| 指标 | 含义 |
|---|---|
| `gld_efficiency` | 全局读利用率(请求字节 / 搬运字节) |
| `gst_efficiency` | 全局写利用率 |
| `l2_sectors_pipe_lsu_mem_global_op_ld` 等 | 精确 sector 搬运计数 |
| `shared_ld_conflict` / `shared_st_conflict` | 共享内存 bank conflict(另一套体系) |

经验法则:利用率 ≥ 80% 算良好,100% 理想;V5 的 A/B 加载应为 100%,As 的转置 scatter 写的 2-way bank conflict 体现在 shared 指标而非 sector 指标上。

---

## 一句话总结

**事务模型 = 32B sector 是"货币",warp 的 32 个地址按 sector 分桶合并,利用率按 sector 内实际用到的字节算;128B 只是 L2 的记账单位,不参与浪费计算。事务数 = sector 数,不是线程数。**
